# Security notes

This is a personal prototype, **not a production-hardened service**.

- This repository is **public**: anyone can read and copy its source. Never rely on code or repository visibility to keep credentials private. Store secrets only in your local, Git-ignored `.env` file.
- Never commit `.env`, `.env.*`, Alibaba API keys, access codes, cloud credentials, or recordings. `.env.example` contains only placeholders.
- Run the robot server on `127.0.0.1`; use a restricted HTTPS tunnel for iPhone access. Do not port-forward Mini directly to the internet. For ngrok, require Google OAuth restricted to your own email address (`ngrok-policy.example.yml`) or Basic Auth with a unique, strong password (`ngrok-password-policy.example.yml`). Keep both local policy files out of Git.
- Rotate any API key or access code immediately if exposed, even in a private commit. Removing it from the latest file does not remove it from Git history.
- The access code, short sessions and session-count throttle are lightweight protections, **not a guaranteed spend cap**. Set quotas and alerts at your provider if possible.
- The continuous camera/microphone feed goes to the AI provider while a session is running. Ask permission before filming/recording others and avoid filming children by default.
- **Child mode:** The child screen has no activity menu; Qwen interprets ordinary spoken requests within one ongoing session. A grown-up must enter the private robot access code and confirm every new paid AI session; the code is cleared after successful authorization. Parent controls are in an accessible modal sheet, **not PIN-protected**, and camera sharing starts **off**.
- **Paid extensions:** Adding time requires reentering the parent code, checked by `/api/parent/authorize` with the same failure throttle as session startup. The code is cleared after submission or dialog dismissal, and pending authorization cannot extend a stopped session. This protects the normal UI flow; session deadlines still run in the browser and are not a provider-enforced spending cap.
- **Mute and stop:** Startup and media attachment preserve the selected mute state. A direct English/Mandarin stop command in a completed transcript stops local tracks and closes WebRTC; this depends on provider transcription and network timing. The visible Stop button remains the immediate local control. Quoted story phrases and negated stop requests do not intentionally terminate capture.
- **Child safety:** Qwen can still produce mistakes or inappropriate content despite the age-appropriate instructions. This prototype is **not certified as child-safe** and must not replace active adult supervision. Keep sensitive personal details and children's faces out of the camera.
- **Dynamic visuals:** When enabled, completed child transcripts and the current validated scene also go to a separate paid Qwen planning endpoint. The planner receives no camera frames. The server and browser validate a bounded image-prompt/game protocol. SVG nodes, sketch fallbacks, generated markup, scripts and arbitrary CSS are rejected; pictures come from the authenticated image API and animations use fixed local presets. This structural validation does not moderate every generated image or word. Displayed visual summaries and local game results can enter voice-session instruction checkpoints; they are not persisted.
- **Local camera reactions:** Off-by-default per-session parent consent and camera sharing enable pinned MediaPipe Face Mesh in a dedicated worker. Transferable camera bitmaps remain on-device and are closed after inference. Only transient geometry reaches the UI; no identities, face embeddings, profiles, expression history or camera recordings are saved. The normal UI sends no `/api/visual/observe` requests and explicitly declines cloud-awareness grants. The legacy endpoint retains its original scoped authorization/rate/frame checks for older clients.
- **Camera behavior:** Local gaze/expression responses may continue during Mini audio and visual games. Child speech retains listening priority; optional spoken hellos require quiet, separate consent, a 60-second cooldown and a maximum of two per session. Pause reactions stops inference/reactions; Pause visual sharing pauses both realtime sharing and local reactions while retaining preview; Stop terminates the worker and releases media. Realtime camera video still reaches Qwen while sharing is on. Local geometry is approximate and cannot establish feelings.
- **Worker policy:** The main page continues to prohibit evaluated/generated JavaScript. The pinned ML runtime needs evaluation inside its separate worker, whose response has a scoped `script-src 'self' 'unsafe-eval'` policy and same-origin-only asset connections. No provider content, grants or code are sent to it. Vendor assets have an explicit static allowlist and immutable versioned paths. See THIRD_PARTY_NOTICES.md for upstream sources and the worker-context correction.
- **Model metadata:** `/api/parent/models` requires the same private code and incorrect-code throttle as startup. It caches bounded read-only native metadata GETs for a minute, filters model identifiers and never generates an image, changes `.env`, chooses a model or returns the key/provider message. Metadata is not a generation/entitlement test.
- **Visual authorization and limits:** Successful parent-authorized SDP exchange can issue an opaque bearer grant, held in browser/server memory for at most 60 minutes. Stop attempts to revoke it and abort in-flight work. A failed revoke leaves the grant usable until expiry; this is not provider-enforced session billing. Grants allow at most 60 planning attempts (8 per minute) and 4 image attempts. Cancelled/failed requests can still incur provider charges. No automatic provider retries are made. Persistent image model/auth/access/quota failure disables artwork across all grants until this server process restarts.
- **Gateway authentication:** Browser-to-Mini visual and awareness calls carry the opaque grant in `X-Mini-Visual-Session`, including Stop revocation, with same-origin credentials. They do not set `Authorization`, allowing Safari to retain ngrok Basic Auth credentials. The server reads grants only from the dedicated header; a missing/expired Mini grant returns JSON without a `WWW-Authenticate` challenge. Server-to-provider API-key authentication remains separate. This fixes a transport conflict and does not replace tunnel authentication or weaken grant scopes.
- **Visual diagnostics and parsing:** Parent diagnostics expose fixed local error categories, configured model names, HTTP status, allowlisted provider codes/parameters and fixed compatibility hints. Raw provider messages, keys, child requests and image URLs are not echoed or logged. The last safe diagnostic remains in tab memory after Stop and clears on a new session, Pause/Resume or refresh; it is not saved to local storage. Complete JSON fences and null/empty known optional placeholders are normalized before strict schema validation; unknown or executable fields remain rejected. Planner failures pause further paid planning calls until explicit parent resumption, without changing the voice connection or making an automatic retry.
- **Speech/visual context:** Normal visual requests now include up to 2000 characters of Mini's current spoken reply, in addition to the child request and current scene. These texts are temporary application data sent to the same configured provider; they are not saved to disk, logs or local storage. Late replies cannot anchor a newer turn. Rule-based game moves/results and tapped story choices use local Safari narration from displayed state, suppress competing realtime game audio and preserve microphone restoration. Local expression animations can continue during narration/activities, but spoken camera greetings cannot interrupt them.
- **Image routing and errors:** The artwork host is the configured Singapore native endpoint, with a server-side workspace header. Only `singapore` and `workspace` routes are configurable. Storage downloads receive no API credentials. Persistent image model/auth/access/quota errors disable image attempts across all grants until restart. No sketch fallback, automatic model substitution, region retry or generated-video request is used. Explicit picture intent requires per-session image consent and keeps the same single-use ticket/image budget, even when it bypasses JSON coordination.
- **Generated pictures:** A configured image model and fresh per-session parent opt-in are both required. The server accepts only a single-use ticket for its latest validated artwork prompt. Storage downloads use HTTPS OSS bucket URLs, reject redirects, carry no API credentials, and are limited to 10 MiB of PNG/JPEG/WebP bytes. The browser decodes those bytes through a temporary blob URL, revoked on exit. No artwork is written to disk or local storage by the app. Provider retention policies still apply.
- **Live conversation:** Spoken requests for stories, guessing games, toy questions and chatting use the existing paid Qwen session, without an activity-selection menu or background auto-start. The separate free tap game is available only while capture is off. Safari speech synthesis supplies one brief local starter after parent connection and may provide one follow-up; Mini temporarily disables its outgoing microphone only while Safari narration actually speaks, then restores it. Tapping the face during local narration interrupts it. Qwen processes the child's subsequent speech.
- **Voice diagnostics:** The local sound meter and Qwen speech-detected state are in Parent setup. The meter never records, stores or transmits amplitude data. A lower acoustic VAD threshold can also pick up background voices. Child speech locally mutes previous playback; provider-side generation/cancellation and actual Safari audio behavior still require device testing.
- **Session activities:** Completed transcripts may advance bounded story choices or riddle counters in browser memory. Only fixed choice identifiers and counters enter activity checkpoints sent via `session.update` between turns, without extra `response.create`. This context may affect billing. Checkpoints and displayed progress are cleared on stop; no activity state or transcripts enter local storage. Model safety remains prompt-based and needs supervised evaluation.
- **Saved settings and local play:** Saving settings is opt-in and uses a fixed allowlist that excludes access codes, API keys, camera sharing, generated-picture consent, visual awareness, spoken greetings and transcripts. The visual-planning preference may be saved; starting paid capture still requires the parent code and confirmation. The free tap game never requests microphone/camera access or creates an AI connection. It is cancelled when capture starts or the page is hidden. Reaction sounds are local, optional and off by default.
- **Mini V6.2 follow-ups:** The system briefly keeps the most recent child and Qwen text transcripts in browser memory to decide whether a question is missing; it does not save these texts to a server or local storage. If enabled, a single local Safari voice follow-up may play after a completed Qwen reply. This fallback may be generic and is not sent to the provider's conversation history. It does not automatically start further AI requests. Do not leave children unattended, and respect when they want to stop.

- `.github/workflows/ci.yml` runs mock/server tests only: it does not access Alibaba, call external AI models or need secrets.

For bugs and security issues in a repository you later publish, avoid including real credentials or private logs in GitHub issues.

- **Camera delivery and pacing:** Smooth camera capture is separate from outbound frame pacing. AI frames preserve aspect ratio; a parent can choose more detail with more data. Local landmark inputs are reduced in the worker and have adaptive single-inference pacing. Diagnostics expose only frame counts, byte counts, sizes and processing times, not ICE addresses or camera imagery. Frame counters cannot prove the model understood the scene. No extra cloud vision polling or paid reconnect is introduced.
- **Closing visuals:** Back to Mini cancels visual work and restores the existing media element without reacquiring capture, revoking grants or sending a new context update. A failed optional update is nonfatal. Actual Stop, page departure and hidden-page handling still release media. The source video remains outside the parent dialog; the monitor reuses its existing stream.
